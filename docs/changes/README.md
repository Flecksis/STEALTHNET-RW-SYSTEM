# Заметки к релизам

Каждое изменение, которое заметят операторы, сопровождается файлом в этой папке. Файл кладётся в том же коммите, что и само изменение.

Имя файла: `ГГГГ-ММ-ДД-коротко.md`, например `2026-11-18-mail-broadcasts.md`.

```markdown
# Рассылки на почту

- В «Рассылках» можно выбрать, куда отправлять: в бот, на почту или туда и туда.
- Если почта не настроена, вариант с почтой недоступен, рядом ссылка на «Настройки → Почта».
```

Первая строка — заголовок, он попадает в название релиза. Дальше 2–5 пунктов: что появилось или исправлено и где это найти. Без внутренних подробностей кода.

Релиз выпускает CI, когда все проверки `main` прошли. Номер релиза совпадает с номером сборки в админке: `0.1.<число коммитов>`. В релиз попадают заметки, добавленные после прошлого релиза. Если новых заметок нет, релиз не выходит, и изменения войдут в следующий.

Проверить, каким получится релиз, можно без публикации: `.github/release.sh --dry-run`.
