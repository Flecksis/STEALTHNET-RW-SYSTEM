# Платёжные системы

Всё настраивается в «Настройки → Оплата». Ключи хранятся зашифрованными: после сохранения поле показывает «Сохранено» и кнопку «Заменить», сам ключ больше не виден.

## Как устроен экран

**Валюта сервиса** — доллары или рубли. Цены, баланс клиентов и платёжки работают в одной валюте, без курсов. В списке видны только платёжки, которые принимают выбранную валюту.

**Строка платёжки** — что она принимает, состояние «Подключена» или «Не настроена», переключатель «Показывать клиентам» и кнопка «Настроить». Пока платёжка не настроена, включить её нельзя.

**Окно «Настроить»:**

- ключи — подписи и подсказки у полей говорят, где их взять в кабинете платёжки;
- «Способы оплаты» — если платёжка принимает несколько способов (СБП, карта, SberPay), отмеченные станут отдельными кнопками у клиента, в этом порядке, каждой можно дать своё название. Если ничего не отмечено, у клиента одна кнопка;
- «Кнопка у клиента» — своё название и пояснение кнопки, пустое поле — текст по умолчанию;
- «Адрес для уведомлений» с кнопкой «Скопировать» — его нужно вписать в кабинете платёжки, чтобы оплаты засчитывались сразу;
- «Проверить подключение» — панель отправит запрос с сохранёнными ключами. Он ничего не создаёт и не списывает. После смены ключей проверка запускается сама.

Адрес уведомлений всегда такой: `https://example.com/api/webhooks/pay/<платёжка>`, где вместо `example.com` — домен вашей панели. Он строится из адреса панели: тот виден в «Настройки → Общие», а задаётся при установке или командой `stealthnet domain`. Без домена платёжки, которым нужен адрес уведомлений, счёт не создадут.

**Где показывать** — у каждой платёжки флажки «Бот», «Кабинет», «Мини-приложение».

> Правила Telegram: в боте и мини-приложении цифровые товары, включая VPN-подписку, продаются только за звёзды. За другие способы оплаты там Telegram может заблокировать бота без предупреждения, поэтому карты и криптовалюту безопаснее оставить только в кабинете.

**Порядок у клиента** — одинаковый в боте, кабинете и мини-приложении, меняется стрелками. Оплата с баланса всегда последняя.

Если поменять поле с адресом у платёжки (например, «Адрес API»), все её сохранённые ключи нужно вставить заново в том же сохранении.

## Баланс, звёзды, автопродление

**С баланса.** Переключатель «Пополнение и оплата с баланса». Клиент пополняет баланс через платёжку (звёздами пополнить нельзя) и платит с него. Пределы пополнения и сколько живёт неоплаченный счёт — «Настройки → Общие». Если баланс выключить, пополнить его нельзя, а остатком можно заплатить, только если его хватает на всю сумму.

**Звёзды Telegram.** Ключей не нужно: звёзды принимает бот сервиса, платёжка становится «Подключена», когда задан токен бота. Цена в звёздах задаётся у каждого срока тарифа, у доп. устройства и пакета трафика. Срок без цены в звёздах звёздами не оплатить. Звёзды возвращаются только всей суммой.

**Автопродление** — на этом же экране: за сколько дней до окончания списывать (по умолчанию за 1), сколько дней повторять попытки (по умолчанию 3, потом автопродление выключится), включать ли его новым клиентам. Списывается с баланса. В рублях можно ещё «Списывать с сохранённой карты через ЮKassa», если на балансе не хватает: карты сохраняются, только когда в настройках ЮKassa включены «Автоплатежи».

## Crypto Pay

- **Ключ:** «API-токен» — в @CryptoBot: Crypto Pay → Create App. Для тестовой сети — в @CryptoTestnetBot.
- **Уведомления:** адрес `…/api/webhooks/pay/cryptopay` вписывается в @CryptoBot: Crypto Pay → приложение → Webhooks.
- «Какие монеты принимать» — например `USDT,TON`, пусто — все. Счёт выставляется в валюте сервиса, клиент платит монетой в @CryptoBot.
- **Тест:** флажок «Тестовая сеть», с токеном из @CryptoTestnetBot. Перед запуском выключите его и вставьте боевой токен.

## GRAM

Оплата переводом GRAM (TON) прямо на ваш кошелёк, без посредника.

- **Поля:** «Адрес кошелька TON» — лучше некастодиальный кошелёк (Tonkeeper, TON Space в Telegram Wallet). «Ключ API toncenter» необязателен: без него оплаты проверяются не чаще раза в секунду, этого хватает. Ключ выдаёт бот @toncenter, нужен ключ для сети Mainnet. «Курс вручную» — цена 1 GRAM в валюте сервиса, пусто — курс с tonapi.io и CoinGecko раз в 5 минут.
- **Уведомлений нет:** панель сама смотрит переводы на кошелёк. Клиент платит на странице оплаты с обязательным комментарием вида `SN-XXXXXXXX`, без него оплата не найдётся.
- **Тест:** флажок «Тестовая сеть» (testnet).
- Ошибки проверки оплат видны красной строкой под платёжкой.

## Heleket

- **Ключи:** «ID мерчанта» — кабинет Heleket → Настройки. «Платёжный API-ключ» — кабинет Heleket → API. Ключ выплат не подходит.
- **Уведомления:** панель передаёт адрес в каждом счёте, в кабинете Heleket указывать не нужно.
- **Способы:** «Любая монета» (выбор на странице Heleket), «USDT TRC-20», «USDT TON», «USDT BEP-20», «Bitcoin», «TON», «Litecoin». Включайте только монеты, разрешённые в кабинете Heleket.
- Если оплата меньше счёта, заказ не выдаётся, а полученная сумма зачисляется на баланс клиента. Излишек при переплате тоже уходит на баланс. Платёж, задержанный проверкой AML, ждёт ручной проверки в «Деньги → Ждут решения», у клиента — ссылка на анкету.

## Cryptomus

- **Ключи:** «ID мерчанта» — кабинет Cryptomus → «Бизнес» → мерчант → «Настройки», поле Merchant ID. «Платёжный API-ключ» — там же (Payment API key), появляется после проверки мерчанта. Ключ выплат не подходит.
- **Уведомления:** панель передаёт адрес в каждом счёте, в кабинете Cryptomus указывать не нужно.
- **Способы** — те же, что у Heleket. Проверка подключения предупредит, если монета не включена у мерчанта.

## Lava

- **Ключи:** «API-ключ» — кабинет Lava → Интеграции → API → Настроить API key. «ID оффера» — оффер продукта с включённой «Цена по запросу API».
- **Уведомления:** придумайте «Ключ вебхука» (до 80 латинских букв и цифр). В Lava: Интеграции → API → Добавить Webhook, URL — адрес из панели, события «Успешная оплата», «Неуспешная оплата», «Успешный возврат», «Получен запрос на чарджбэк», аутентификация «API key вашего сервиса» с этим ключом.
- **Способы:** в рублях — «Карта» и «СБП», в долларах — «Карта» (Visa и Mastercard любых стран) и «PayPal».
- Для оплаты нужна почта клиента. Возвраты делаются в кабинете Lava, панель отметит их по уведомлению.

## ЮKassa

- **Ключи:** «shopId» и «Секретный ключ» — кабинет ЮKassa → Интеграция → Ключи API.
- **Уведомления:** кабинет ЮKassa → «Интеграция → HTTP-уведомления», отметьте события о платежах и возвратах. Каждое уведомление панель перепроверяет запросом к ЮKassa.
- **Способы:** «Все способы», «Карта», «СБП», «SberPay», «T-Pay», «ЮMoney», «Кредит от Сбера» (от 3000 ₽).
- «Автоплатежи» — сохранять способ оплаты для автопродления. Включайте, только если ЮKassa подключила магазину автоплатежи.
- Чеки 54-ФЗ: «Ставка НДС» (пусто — без чека) и «Система налогообложения» (только для сторонней онлайн-кассы).
- **Тест:** вставьте shopId и ключ тестового магазина ЮKassa, проверка подключения скажет, что магазин тестовый.

## Platega

- **Ключи:** «MerchantId» и «Секрет» — кабинет Platega → Настройки.
- **Уведомления:** настройки магазина Platega, поле адреса уведомлений.
- **Способы:** «СБП», «Карта», «Иностранная карта», «Криптовалюта», «SberPay», «Все способы». Без отмеченных — одна кнопка «СБП».
- Спор по платежу приходит в «Ждут решения» и в группу уведомлений, возврат до конца спора невозможен.

## ЮMoney

- **Поля:** «Номер кошелька» (обычно начинается с 4100) и «Секрет уведомлений» — ЮMoney → HTTP-уведомления.
- **Уведомления:** адрес вписывается там же, в настройках HTTP-уведомлений кошелька.
- **Способы:** «Карта» (банковская карта через ЮMoney) и «ЮMoney» (из кошелька).
- Проверить подключение без оплаты нельзя: проверьте небольшим платежом.

## CloudPayments

- **Ключи:** «Public ID» (начинается с `pk_`) и «Пароль для API» — кабинет CloudPayments → Сайты.
- **Уведомления:** четыре адреса. В настройках сайта включите уведомления Check, Pay, Fail и Refund, каждое на свой адрес из панели. Метод GET или POST, кодировка UTF-8, формат CloudPayments.
- **Способы:** «Все способы» (страница CloudPayments) и «СБП».
- **Тест:** флажок «Тестовый режим». В нём засчитываются только тестовые оплаты, без него — только настоящие.

## Overpay

- **Поля:** «ID проекта», «Логин» и «Пароль» API от Overpay, «Сертификат клиента». Сертификат — сертификат и закрытый ключ одним текстом PEM: файл `.p12` переводится командой `openssl pkcs12 -in cert.p12 -out cert.pem -nodes` (при ошибке unsupported добавьте `-legacy`), вставьте весь текст `cert.pem`.
- **Уведомления:** панель передаёт адрес в каждом счёте, в кабинете Overpay указывать не нужно.
- **Способы:** «Все способы», «Карта», «СБП».

## RollyPay

- **Ключи:** «API-ключ» (начинается с `rpk_`) и «Ключ подписи уведомлений» (signing_secret) — выдаются при создании кассы.
- **Уведомления:** поле callback_url в настройках кассы. Если доступа к кабинету нет, адрес можно передать поддержке RollyPay. Проверка подключения покажет, если там осталась заглушка новой кассы.
- **Способы:** «СБП», «Карта», «Иностранная карта», «Криптовалюта», «Все способы».
- **Тест:** флажок «Тестовый режим» — оплату имитирует кнопка на странице RollyPay, тестовые оплаты засчитываются только в нём.
- Часы сервера должны идти точно: уведомления с расхождением больше 15 минут не принимаются.

## MulenPay

- **Ключи:** «ID магазина» — раздел «Магазины». «API-ключ» и «Секретный ключ» — настройки магазина. «Ставка НДС в чеке» — если не знаете, оставьте «Без НДС».
- **Уведомления:** адрес указывается в настройках магазина. MulenPay не повторяет уведомления, поэтому панель ещё и спрашивает статус счёта сама.
- Возврат из панели — только на всю сумму, часть возвращается в кабинете MulenPay.

## PayPalych

- **Ключи:** «API-токен» — кабинет PayPalych (Pally, pal24.pro) → API-интеграция, целиком, вместе с числом и чертой в начале (`72|…`). «ID магазина» — кабинет → Магазины.
- **Уведомления:** три адреса. В настройках магазина: первый — Result URL, второй — Refund URL, третий — Chargeback URL. Success URL и Fail URL — куда вернётся покупатель, например ваш сайт или бот.
- **Способы:** «СБП», «Карта», «Все способы».
- Возвраты через API включает поддержка PayPalych. Если в кабинете включён белый список IP, добавьте туда адрес сервера панели.

## Kassa.ai

- **Ключи:** «ID магазина», «API-ключ» и «Секретное слово 2» — кабинет Kassa.ai, настройки магазина.
- **Уведомления:** «URL оповещения» в настройках магазина, метод POST.
- **Способы:** «СБП», «Карта», «SberPay». Без отмеченных — СБП.
- **Тест:** включается в магазине Kassa.ai, а тестовые оплаты панель засчитывает как настоящие. После проверки выключите тестовый режим.

## AuraPay

- **Ключи:** «ID кассы» — настройки кассы → «Уникальный ID кассы». «API-ключ» и «Секретный ключ для Callback» — настройки кассы → «Секретные ключи API», ключ показывается один раз.
- **Уведомления:** панель передаёт адрес с каждым счётом. Если в настройках кассы стоит адрес старого бота, замените его адресом из панели.
- **Способы:** «СБП», «Карта», «Все способы».
- Возвратов через API нет: деньги возвращает поддержка AuraPay.

## Tribute

- **Ключ:** «API-ключ» — Tribute → кабинет автора → ⋯ → «Настройки» → «API-ключи» → «Сгенерировать ключ».
- **Уведомления:** там же, поле Webhook URL.
- **Товары для пополнения.** Создайте в Tribute цифровые товары на суммы пополнения, например 300, 500 и 1000 ₽, и отметьте их в панели после «Обновить список из Tribute». Отмеченные суммы станут кнопками пополнения. При покупке тарифа клиент оплачивает самый дешёвый товар не меньше цены, остаток остаётся на балансе. Без отмеченных товаров кнопки Tribute нет. Покупка неотмеченного товара баланс не пополняет: она ждёт решения в «Деньги → Ждут решения».
- **Подписки Tribute** можно привязать к тарифу и сроку: новая подписка выдаёт тариф, каждое продление — ещё на срок. Деньги за непривязанный срок идут на баланс.
- Оплату панель находит по Telegram ID покупателя, поэтому Tribute видят только клиенты с привязанным Telegram.

## WATA

- **Ключ:** «Токен доступа» — кабинет WATA → Терминалы → терминал → Access Token.
- **Уведомления:** в кабинете, в настройках терминала, у каждого терминала свой адрес.
- WATA принимает запросы только с согласованных IP: если ссылки на оплату не создаются, передайте менеджеру WATA адрес сервера панели.
- **Тест:** флажок «Тестовая среда» — песочница WATA с тестовыми картами, токен выдаётся в тестовом кабинете.

## Freekassa

- **Ключи:** «ID магазина», «API-ключ» и «Секретное слово 2» — настройки магазина. «Секретное слово 1» нужно для кнопки «Все способы».
- **Уведомления:** «URL оповещения» в настройках магазина, метод POST. Там же — адрес возврата клиента после оплаты, например кабинет.
- **Способы:** «СБП», «Карта», «SberPay», «Все способы».
- Freekassa требует IP при создании заказа: панель передаёт внешний IPv4 своего сервера, его можно указать вручную в «IP-адрес сервера».
- «Оповещения только с адресов Freekassa» включайте, если панель видит настоящие адреса, а не адрес своего прокси.
- Если уже оплаченный счёт оплатили ещё раз, панель сначала проверяет эту оплату через API Freekassa и только потом зачисляет её на баланс. Если Freekassa такую оплату не подтвердила, оповещение остаётся в журнале уведомлений с причиной. Если API не ответил, Freekassa пришлёт оповещение снова.
- **Тест:** включается в настройках магазина Freekassa.

## Robokassa

- **Ключи:** «Идентификатор магазина», «Пароль №1» и «Пароль №2» — кабинет Robokassa → Мои магазины → Технические настройки. «Алгоритм хеша» — как в поле «Алгоритм расчёта хеша» там же (RIPEMD-160 не поддерживается). «Пароль №3» нужен для возвратов из панели.
- **Уведомления:** Result URL в технических настройках магазина, метод POST. В Success URL и Fail URL укажите, куда вернуть клиента, например кабинет.
- **Способы:** «Карта», «СБП», «SberPay», «T-Pay», «Все способы».
- **Тест:** флажок «Тестовый режим» и тестовые пароли №1 и №2 из «Параметров проведения тестовых платежей». Тестовые оплаты засчитываются только в этом режиме.

## CisPay

- **Ключи:** «Shop ID» и «API-ключ» (вида `cis_sec_…`) — кабинет CisPay → «Настройки магазина».
- **Уведомления:** адрес для вебхуков в «Настройках магазина». Каждое уведомление панель сверяет запросом статуса к CisPay.
- **Способы:** «СБП», «Карта» (от 50 ₽), «Криптовалюта», «Все способы». В долларах CisPay принимает только криптовалюту, у клиента одна кнопка «Криптовалюта».
- **Тест:** платежи из «Песочницы» кабинета засчитываются, только если включено «Засчитывать тестовые платежи». Перед приёмом настоящих оплат выключите.
- Возврат из панели — на всю сумму или на часть. Оплату криптовалютой CisPay не возвращает.

## ParityPay

- **Ключи:** «ID кассы», «Секретный ключ №1» и «Секретный ключ №2» — кабинет ParityPay → настройки кассы.
- **Уведомления:** панель передаёт адрес с каждым счётом. Если в настройках кассы стоит адрес старого бота, замените его адресом из панели.
- **Способы:** «СБП», «Карта», «Все способы».
- Возвратов через API нет: деньги возвращает поддержка ParityPay.

## Когда что-то пошло не так

- **«Деньги → Уведомления платёжек»** (тот же журнал открывается пунктом «Уведомления платёжек» в меню) — всё, что платёжки присылали панели, и чем это закончилось: засчитано, повтор, пропущено, отклонено (например, неверная подпись), сумма не сошлась, ошибка обработки. Уведомление с ошибкой обработки можно обработать ещё раз: если оплата уже засчитана, деньги второй раз не зачислятся. Уведомления хранятся 30 дней, не прошедшие проверку подписи — 3 дня.
- **«Деньги → Ждут решения»** — заказы на ручной проверке, оплаты звёздами на разборе, незавершённые возвраты, споры и чарджбэки, деньги, которые ждут ручного зачисления.
- **«Проверить подключение»** показывает, приходили ли уведомления с неверной подписью за 30 дней: обычно это значит, что ключ в панели не совпадает с ключом в кабинете платёжки.
- Недоплата не засчитывается никогда, переплата засчитывается.

## Возвраты

У оплаченного платежа в «Деньгах» есть кнопка «Вернуть», в карточке клиента — «Вернуть деньги» (нужно право «Возвраты»). В окне:

- сумма — можно вернуть часть;
- куда: «Через …» платёжку (если она умеет возвраты, подтверждение может идти несколько дней), «На баланс» или «Уже вернули вне панели» — только отметка;
- что сделать с подпиской: «Оставить», «Снять дни» (столько, сколько добавил заказ) или «Отключить»;
- причина — её увидят администраторы в истории клиента.

Пополнение баланса возвращается только через платёжку, оплата с баланса — только на баланс. Если платёжка не подтвердила возврат за сутки, он попадает в «Ждут решения» → «Заявки на возврат без ответа».
