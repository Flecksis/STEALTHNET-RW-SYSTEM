# Внешние модули

Внешний модуль — отдельная программа, которая дополняет панель: шлёт клиентам свои сообщения, выгружает оплаты в CRM, показывает свой отчёт и так далее. Модуль работает на вашем сервере или где угодно, на любом языке. Панель не запускает его код и не даёт ему доступа к базе: она только шлёт модулю события с подписью и выдаёт ключ API с правами, которые оператор подтвердил при установке.

Модуль описывается одним JSON-файлом. Оператор загружает этот файл в «Модули → Установить модуль», читает, что модуль получит, и подтверждает. Готовый пример — [examples/module-hello](../examples/module-hello).

## Как устроено

1. Оператор загружает файл описания. Панель проверяет его и показывает человеческими словами: какие события будут уходить модулю, какие права получит его ключ, куда уходят события, есть ли у модуля своя страница.
2. После подтверждения панель выпускает ключ API (`snk_…`) и секрет подписи (`whsec_…`) и показывает их один раз. Оператор передаёт их модулю, например в переменных окружения.
3. Когда происходит событие, на которое подписан модуль, панель шлёт его на адрес модуля запросом `POST` с подписью.
4. Модуль обращается к API панели своим ключом: читает клиентов, пишет им в бот и так далее — в пределах подтверждённых прав.
5. Если у модуля есть страница, она открывается внутри админки, а модуль узнаёт, кто из администраторов её открыл.

Устанавливать, обновлять и удалять модули может администратор с правами «Модули» и «Настройки», и только из своей сессии в админке: ключом API этого не сделать. Выключить модуль и поменять его настройки можно с правом «Модули».

## Файл описания

```json
{
  "format": 1,
  "id": "hello",
  "name": "Привет",
  "version": "1.0.0",
  "author": "Студия Пример",
  "description": "Здоровается с новыми клиентами в боте и благодарит за оплату",
  "site": "https://example.com/hello",
  "webhook": "https://hello.example.com/stealthnet/events",
  "events": ["client_registered", "payment_paid"],
  "permissions": ["clients_read", "clients_write", "money"],
  "page": {
    "url": "https://hello.example.com/admin",
    "title": "Привет: журнал",
    "permission": "modules"
  },
  "settings": [
    { "key": "greeting", "type": "text", "label": "Текст приветствия", "large": true, "default": "Спасибо, что с нами!" },
    { "key": "thank_after_payment", "type": "flag", "label": "Благодарить за оплату", "default": true },
    { "key": "crm_token", "type": "secret", "label": "Токен CRM", "hint": "Из личного кабинета CRM" },
    { "key": "per_hour", "type": "number", "label": "Не больше сообщений в час", "default": 20 },
    {
      "key": "tone",
      "type": "select",
      "label": "Как обращаться",
      "options": ["formal", "friendly"],
      "labels": ["На вы", "На ты"],
      "default": "friendly",
      "required": true
    }
  ]
}
```

| Поле | Обязательно | Что это |
|---|---|---|
| `format` | да | Версия формата описания. Сейчас только `1` |
| `id` | да | Имя модуля: 2–40 символов, латиница в нижнем регистре, цифры и дефис, первая — буква. Не совпадает со встроенными модулями (`promo`, `referral`…). По `id` панель узнаёт модуль при обновлении |
| `name` | да | Название в списке модулей, до 60 символов |
| `version` | да | Версия модуля, любая строка до 30 символов |
| `author` | да | Автор, до 80 символов. Оператор видит его при подтверждении |
| `description` | нет | Что делает модуль, до 300 символов |
| `site` | нет | Сайт модуля, `https://…` |
| `webhook` | если есть `events` | Адрес, куда панель шлёт события |
| `events` | нет | На какие события подписан модуль — см. «События» |
| `permissions` | нет | Права ключа API модуля — см. «Права» |
| `page` | нет | Страница модуля внутри админки — см. «Страница в админке» |
| `settings` | нет | Поля настроек, до 30 — см. «Настройки» |

Лишние поля и опечатки в именах полей — ошибка: панель покажет, что не так, со ссылкой на поле, например `events[1]: неизвестное событие «payment_done»`. Файл — не больше 64 КБ.

### Адреса

`webhook` и `page.url` — это `https://…` с доменом или публичным IP-адресом. На этот же сервер можно и без шифрования: `http://localhost`, `http://127.0.0.1` или `http://[::1]` с любым портом.

Нельзя:

- адреса внутренней сети: `10.x`, `172.16–31.x`, `192.168.x`, `100.64–127.x`, `169.254.x`, `0.0.0.0`, `fc00::/7`, `fe80::/10` и другие служебные. Панель проверяет и имя домена при каждой доставке: если домен ведёт во внутреннюю сеть, событие не уйдёт;
- логин и пароль в адресе и часть после `#`;
- адрес самой панели.

Перенаправления (`301`, `302`…) панель не выполняет: такой ответ считается ошибкой доставки.

## События

Модуль получает только те события, на которые подписан, и только пока он включён. Каждое событие требует права на чтение этих данных: без права в `permissions` файл не примется.

| Событие | Когда | Нужно право | `data` |
|---|---|---|---|
| `client_registered` | Клиент зарегистрировался | `clients_read` | `client_id`, `source` (`bot`, `miniapp`, `web`, `admin`, `import`, `migration`), `start_param` — параметр ссылки или `null` |
| `client_blocked` | Клиент заблокирован | `clients_read` | `client_id`, `reason` |
| `client_unblocked` | Клиент разблокирован | `clients_read` | `client_id` |
| `payment_paid` | Оплата прошла | `money` | `payment_id`, `order_id`, `client_id`, `order_kind`, `amount`, `provider` |
| `payment_refunded` | Оплата возвращена | `money` | `payment_id`, `order_id`, `client_id`, `amount` |
| `order_fulfilled` | Покупка выдана | `clients_read` | `order_id`, `client_id`, `order_kind`, `subscription_id` |
| `subscription_created` | Подписка выдана | `clients_read` | `subscription_id`, `client_id`, `kind` (`paid`, `trial`, `gift`, `promo`, `manual`, `custom`) |
| `subscription_renewed` | Подписка продлена | `clients_read` | `subscription_id`, `client_id`, `expire_at` |
| `tariff_changed` | Тариф сменился | `clients_read` | `subscription_id`, `client_id`, `from`, `to` — номера тарифов |
| `subscription_status_changed` | Статус подписки изменился | `clients_read` | `subscription_id`, `client_id`, `from`, `to` (`active`, `limited`, `expired`, `disabled`) |
| `balance_changed` | Баланс изменился | `money` | `client_id`, `wallet` (`main`, `referral`), `kind` — причина, `delta` |
| `ticket_opened` | Новое обращение в поддержку | `support` | `ticket_id`, `client_id` |
| `ticket_answered` | Поддержка ответила клиенту | `support` | `ticket_id`, `client_id` |

`order_kind` — `new`, `renewal`, `change`, `top_up`, `trial`, `module`, `admin_grant`, `module_grant`. Суммы — `{"minor": 69900, "currency": "RUB"}`: `minor` в копейках или центах, для `XTR` — в звёздах. Время — ISO 8601 в UTC.

Ещё два служебных события приходят без подписки:

- `ping` — оператор нажал «Проверить связь» в карточке модуля. `data` пустой;
- `settings_changed` — оператор сохранил настройки модуля. В `data.keys` — какие поля изменились; сами значения модуль читает через API.

### Запрос с событием

```http
POST /stealthnet/events HTTP/1.1
Content-Type: application/json
User-Agent: stealthnet/0.1.0
webhook-id: evt_1532
webhook-timestamp: 1763467391
webhook-signature: v1,K5oZfzN95Z9UVu1EsfQmfVNQhnkZ2pj9o9NDN/H/pI4=

{"id":"evt_1532","type":"payment_paid","module":"hello","occurred_at":"2026-11-18T12:03:11.402Z","data":{"payment_id":812,"order_id":790,"client_id":41,"order_kind":"renewal","amount":{"minor":69900,"currency":"RUB"},"provider":"yookassa"}}
```

`id` у события постоянный: при повторной доставке он тот же. Служебные события получают `id` вида `msg_…`.

### Проверка подписи

Подпись устроена по открытой спецификации [Standard Webhooks](https://www.standardwebhooks.com/), поэтому подойдут и их готовые библиотеки.

1. Ключ — секрет без приставки `whsec_`, раскодированный из base64.
2. Строка для подписи — `{webhook-id}.{webhook-timestamp}.{тело запроса как есть}`.
3. Подпись — HMAC-SHA256 этой строки, в base64, с приставкой `v1,`. Сравнивайте её с заголовком `webhook-signature` за постоянное время.

Кроме подписи, модуль должен:

- отклонять события, у которых `webhook-timestamp` отличается от его часов больше чем на 5 минут;
- помнить `webhook-id` обработанных событий и не выполнять одно и то же дважды.

Пример на Python:

```python
import base64, hashlib, hmac, time

def check(secret: str, headers, body: bytes) -> bool:
    key = base64.b64decode(secret.removeprefix("whsec_"))
    msg_id = headers["webhook-id"]
    stamp = headers["webhook-timestamp"]
    if abs(time.time() - int(stamp)) > 300:
        return False
    signed = f"{msg_id}.{stamp}.".encode() + body
    expected = "v1," + base64.b64encode(hmac.new(key, signed, hashlib.sha256).digest()).decode()
    return any(hmac.compare_digest(expected, part) for part in headers["webhook-signature"].split(" "))
```

### Ответ модуля и повторы

- Любой код `2xx` за 10 секунд — событие доставлено. Тело ответа не нужно; первые 1000 символов попадут в журнал доставки.
- Всё остальное — ошибка: другой код, перенаправление, тайм-аут, нет соединения. Панель повторит через 30 секунд, 2 минуты, 10 минут, 30 минут, час, 3 часа и 6 часов. После восьмой неудачи событие помечается «не доставлено»: его можно отправить снова из журнала в карточке модуля — по одному или все недоставленные сразу.
- Порядок событий не гарантирован: повтор старого события может прийти после нового. Сверяйтесь с `occurred_at` и при необходимости с API.
- Модуль, который долго не отвечает, не тормозит ни панель, ни другие модули: доставка идёт отдельно для каждого модуля, не больше четырёх запросов к одному модулю одновременно.
- Отвечайте быстро, а долгую работу делайте после ответа.

## Права

Ключ API модуля работает как вход в админку с подтверждёнными правами. Права ключа не шире прав администратора, который установил модуль: при установке панель не даст подтвердить право, которого нет у самого администратора, а если администратора потом ограничат или отключат, ключ тоже сузится или перестанет работать.

| Право | Что даёт |
|---|---|
| `clients_read` | Видеть клиентов, их подписки и историю |
| `clients_write` | Менять подписки и баланс клиентов, писать им, блокировать и удалять |
| `money` | Видеть оплаты, заказы и выручку, разбирать спорные оплаты |
| `refunds` | Возвращать клиентам деньги |
| `tariffs` | Менять тарифы и цены |
| `infrastructure` | Ноды, сквады и хосты Remnawave |
| `support` | Читать обращения и отвечать клиентам, в том числе с файлами |
| `marketing` | Промокоды, рассылки, рефералы, конкурсы |
| `modules` | Включать и настраивать встроенные модули |
| `settings` | Менять настройки панели, в том числе ключи платёжных систем и бота |

Права `admins` и `clients_login` (выдать клиенту пароль для сайта и снять ему вход по коду из приложения) модулю дать нельзя. Ключ модуля не может выпускать ключи, ставить и удалять модули, смотреть журнал доставки.

## API

Модуль передаёт ключ в заголовке `Authorization: Bearer snk_…`. Ключ работает, пока модуль включён: у выключенного и удалённого модуля запросы получают `401`.

Свои данные и настройки модуль читает так:

```http
GET /api/admin/ext-modules/me
Authorization: Bearer snk_…
```

```json
{
  "id": "hello",
  "name": "Привет",
  "version": "1.0.0",
  "enabled": true,
  "events": ["client_registered", "payment_paid"],
  "permissions": ["clients_read", "clients_write", "money"],
  "settings": {
    "greeting": "Спасибо, что с нами!",
    "thank_after_payment": true,
    "crm_token": "значение секретного поля или null",
    "per_hour": 20,
    "tone": "friendly"
  }
}
```

Остальное — тот же API, которым пользуется админка. Например:

| Запрос | Право | Что делает |
|---|---|---|
| `GET /api/admin/clients?limit=50` | `clients_read` | Список клиентов |
| `GET /api/admin/clients/{id}` | `clients_read` | Карточка клиента |
| `GET /api/admin/subscriptions/{id}` | `clients_read` | Подписка |
| `POST /api/admin/clients/{id}/message` с `{"text": "…"}` | `clients_write` | Сообщение клиенту в бот |
| `GET /api/admin/payments` | `money` | Оплаты |

Все действия ключа записываются в журнал действий от имени администратора, который выпустил ключ.

## Настройки

Если в описании есть `settings`, в карточке модуля появляется форма — такая же, как у встроенных модулей. Модуль получает значения через `GET /api/admin/ext-modules/me`, а после каждого сохранения — событие `settings_changed`.

| Поле | Что это |
|---|---|
| `key` | Имя поля: латиница в нижнем регистре, цифры и `_` |
| `type` | `text`, `secret`, `number`, `flag`, `url` или `select` |
| `label` | Подпись поля, до 80 символов |
| `hint` | Подсказка под полем, до 300 символов |
| `required` | Без него настройки не сохранятся. По умолчанию `false` |
| `default` | Значение по умолчанию. У `secret` его не бывает |
| `large` | Только для `text`: большое поле до 4000 символов вместо 300 |
| `options`, `labels` | Только для `select`: значения и подписи к ним |

Секретные поля хранятся зашифрованными и в админке не показываются — только «задано» или нет. Модуль получает их значения в `GET /api/admin/ext-modules/me`.

При обновлении описания значения полей, которые остались с тем же типом, сохраняются; удалённые поля стираются.

## Страница в админке

Если в описании есть `page`, в карточке модуля появляется ссылка «Открыть страницу». Страница открывается во встроенном окне (`iframe` с `sandbox`): скрипты, формы и всплывающие окна работают, а доступа к самой админке, её сессии и кукам у страницы нет. Страница не может лежать на адресе самой панели. Открыть её могут администраторы с правом из `page.permission` (по умолчанию `modules`).

Панель добавляет к адресу страницы параметр `sn_token` — короткий подписанный токен. По нему модуль узнаёт, кто из администраторов открыл страницу:

- это JWT с алгоритмом HS256, подписанный тем же ключом, что и события (секрет без `whsec_`, раскодированный из base64);
- `iss` — `stealthnet`, `aud` — `module:<id модуля>`, `exp` — через 5 минут после выдачи;
- `admin_id`, `email`, `role` и `permissions` — кто открыл страницу и что ему можно.

Проверяйте подпись, `aud` и `exp`. Токен не даёт доступа к API панели — для API у модуля свой ключ.

Чтобы получить свежий токен, не перезагружая страницу, отправьте сообщение родительскому окну:

```js
window.parent.postMessage({ type: 'stealthnet:token' }, '*');
window.addEventListener('message', (event) => {
  if (event.data?.type === 'stealthnet:token' && event.data.token) {
    useToken(event.data.token, event.data.expires_at);
  }
});
```

Админка отвечает только своему встроенному окну и только на адрес страницы модуля.

## Установка, обновление, удаление

- **Установка.** «Модули → Установить модуль», выбрать файл, проверить, что получит модуль, подтвердить. Ключ API и секрет подписи показываются один раз.
- **Обновление.** В карточке модуля — «Обновить из файла». Панель покажет, что добавится и что уберётся, и попросит подтвердить заново. Ключ и секрет остаются прежними, права ключа меняются на новые.
- **Новый адрес.** Если в новом файле другой адрес для событий или страницы, окно покажет, какой адрес сейчас. Обновление пройдёт, только если подтверждён именно новый адрес (поля `webhook` и `page` в запросе установки), иначе отказ `ext_modules.confirm`. Запись `ext_module.updated` в журнале действий хранит старый и новый адрес (`moved`). Секрет подписи на адрес не уходит: туда идут только события с подписью и короткий пропуск администратора на страницу модуля.
- **Выключение.** Переключатель в списке модулей или в карточке. События перестают уходить (те, что ждали повтора, отменяются), ключ API не принимается. После включения ключ снова работает и уходят новые события; события, случившиеся за время выключения, модуль не получит.
- **Новые ключ и секрет.** В карточке модуля — «Выпустить новые». Старый ключ сразу отзывается, старый секрет перестаёт подходить.
- **Удаление.** Ключ API отзывается, секреты, настройки и журнал доставки стираются.

Журнал доставки хранится 14 дней.
